# 開発版の確認結果

2026年11月14日。元店舗の本番を変更せず、別の一時保存先・送信無効の状態で確認した。終了後に確認用の実行処理を止め、一時的な予約データを削除した。

## 通った確認

- 2店舗の開設。初期メニュー・スタッフ・予約・回数券が空であること。
- 他店のログイン状態、契約ID、予約番号では記録や契約を操作できないこと。
- メニュー、担当者、部屋、対応する部屋、勤務時間を登録し、空き枠を取得して「テスト」名義の予約を保存。再送でも同じ予約番号になること。
- 無料期間終了後に新しい操作を止め、既存記録を読むことができること。
- 再起動と実行処理の入れ替え後もメニュー・予約を保持すること。保存ファイルは所有者だけが読み書きできること。
- 料金の誤設定、不正な署名、未払い、数量変更、解約を扱い、同時申込みで支払いページを二重作成しないこと。Stripeの署名処理は実ライブラリを使用し、決済通信は代用品で検証した。
- Chromeで店舗開設、契約管理、空の予約画面、管理画面へのログイン、主要ページ、8言語の追加文言、スマホ幅390pxを確認した。画面の実行エラーなし。
- 元店舗の地図、写真、名称、連絡先、規約の固定表示を複製先から除去。地図は各店舗の登録住所を使う。
- 公開用一式を別の一時フォルダに展開し、依存する部品の導入、起動、空店舗の開設、予約画面の表示、終了時の保存と起動記録の解除を確認した。

## 実施方法

`npm test` と `npm run test:ui`。後者はMacのGoogle Chromeを使う。別の場所にある場合は `CHROME_PATH` を指定する。画面記録はGit対象外の `test-results/` に保存する。

## まだ確認できていない範囲

Stripeへの実接続と実際の支払い・返金、公開サーバーと証明書、予約メールの実送信、外部バックアップと復元、大量店舗の同時利用、全管理画面・全翻訳・全操作の元サイトとの完全照合。これらの合格や売上発生を示す結果ではない。公開前に残る作業はREADMEを参照する。

## 2026年11月22日の追加確認

- 予約サービスの `npm test` 6件が成功。税計算に必要な請求先の収集、税設定の確認前には本番課金を止める設定、無料期間残り48時間未満でも前倒し課金しない動作を含む。決済は引き続き代用品で、実請求は行っていない。
- 導入相談サイトは型検査、公開用ビルド、入力の試験3件が成功。ローカルの独立したD1に限り、HTTP試験2件でページ表示、匿名操作の拒否、相談保存、重複防止、同意必須、送信上限を検証。
- ローカル確認用の相談6件は「テスト担当」名義。運営者の読取・更新、別の利用者の拒否、同時更新の衝突、robotsとsitemapを確認。確認用サーバーは停止済み。ローカルDBを公開一式に含めない。
- Sitesの公開処理が成功。外部から紹介・条件等のページを閲覧し、相談一覧は匿名・偽の認証ヘッダーのいずれでも403になることを確認。公開先に確認用の相談・予約を入れていない。
- 掲載画像は以前に撮影した空の検証店舗を目視確認。実顧客やスタッフの情報を含まない。
- 今回はWork設定でローカルブラウザ操作が無効のため、新規紹介ページのブラウザでの操作・スマホの目視確認は未実施。HTTPとビルドの結果を、画面操作の合格と扱わない。
