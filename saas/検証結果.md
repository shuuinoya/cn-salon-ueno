# 開発版の確認結果

2026年11月14日。元店舗の本番を変更せず、別の一時保存先・送信無効の状態で確認した。終了後に確認用の実行処理を止め、一時的な予約データを削除した。

## 通った確認

- 2店舗の開設。初期メニュー・スタッフ・予約・回数券が空であること。
- 他店のログイン状態、契約ID、予約番号では記録や契約を操作できないこと。
- メニュー、担当者、部屋、対応する部屋、勤務時間を登録し、空き枠を取得して「テスト」名義の予約を保存。再送でも同じ予約番号になること。
- 無料期間終了後に新しい操作を止め、既存記録を読むことができること。
- 再起動と実行処理の入れ替え後もメニュー・予約を保持すること。保存ファイルは所有者だけが読み書きできること。
- 料金の誤設定、不正な署名、未払い、数量変更、解約を扱い、同時申込みで支払いページを二重作成しないこと。Stripeの署名処理は実ライブラリを使用し、決済通信は代用品で検証した。
- Chromeで店舗開設、契約管理、空の予約画面、管理画面へのログイン、主要ページ、8言語の追加文言、スマホ幅390pxを確認した。画面の実行エラーなし。
- 元店舗の地図、写真、名称、連絡先、規約の固定表示を複製先から除去。地図は各店舗の登録住所を使う。
- 公開用一式を別の一時フォルダに展開し、依存する部品の導入、起動、空店舗の開設、予約画面の表示、終了時の保存と起動記録の解除を確認した。

## 実施方法

`npm test` と `npm run test:ui`。後者はMacのGoogle Chromeを使う。別の場所にある場合は `CHROME_PATH` を指定する。画面記録はGit対象外の `test-results/` に保存する。
