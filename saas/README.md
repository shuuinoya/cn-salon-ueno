# 他店向け予約サービス（正式名称未定）

元の予約サイト・店舗管理画面のプログラムを使い、空の店舗用に分けた開発版です。既存店の本番には反映しません。元の `server.js`・`demo-api.js`・`persist.js`・画面ファイルは編集していません。

## 手元で開く

Node.js 24 以上が必要です。このフォルダで次を実行します。

```sh
npm ci
npm run build
npm test
npm start
```

- サービス紹介・店舗開設：<http://localhost:5610>
- 収支試算：<http://localhost:5610/profit>
- 店舗開設時に `my-salon` と指定した例：<http://my-salon.localhost:5610>
- 同じ店舗の管理画面：<http://my-salon.localhost:5610/cnsalon-board>
- 最初の店舗管理者ID：`owner`。パスワードは開設時に指定したものです。契約管理のログインはメールアドレスです。

無料期間は14日。顧客・予約・スタッフ・メニュー・回数券は空です。開設した店舗名と管理者だけ登録します。店舗情報、ブース、メニュー、スタッフ、対応メニュー、シフトを管理画面で設定して使います。新しい店舗独自の紹介文・写真は未登録です。現在の店舗と全く同じ見栄えで販売できるという最終確認は、公開前に実際の操作と全ページを照合して行う必要があります。

`npm run build` はGitで追跡されているプログラムだけを選び、`runtime/` に生成します。本番の `data/`、メール設定、秘密ファイル、写真、起動用設定を読みません。保存されたページの見本本文を除き、元の画面部品に空の店舗データを渡します。元ファイルの構成が変わった場合は、置換箇所を検査して停止します。生成結果をGitに入れません。

画面確認は `npm run test:ui`（Google Chromeが必要）。確認結果は `検証結果.md` に記載しています。

## 公開先へ渡す一式を作る

`node package-release.cjs` で `releases/reservation-service.tar.gz` を作ります。実行用プログラムの許可リストだけを選び、顧客データ・秘密設定・確認用データを含めません。ファイル確認用の `SHA256SUMS` を添付します。元の作業フォルダ全体をアップロードしないでください。

同時に作る `releases/収支試算.html` は、サービスを起動せずブラウザで開ける試算表です。店舗数・料金・経費・税金の仮定を変えられます。

展開先では `npm ci --omit=dev`、公開先の非公開設定を指定した `npm start` で起動します。展開先では生成済みの `runtime/` を使用するため、Gitや元店舗のフォルダは不要です。同梱Dockerfileはこの展開先で使用するものです。保存用の永続領域を `/app/data` に接続し、サービス用ユーザーが書き込めるようにします。実際の公開・Docker上での実行試験は未実施です。

公開入口ではHTTPS、サービス本体と店舗用サブドメインの転送を設定します。内部ポート5610をインターネットに直接公開しません。共有ストレージに複数の本サービスを同時に起動しないでください。保存・復元、証明書更新、監視、通知の運用を準備してから外部の予約を受け付けます。

## 分離と保存

- 契約情報は `data/service.sqlite`、店舗の記録は `data/stores/<店舗番号>/state.json`。本番と別の保存先です。
- 店舗ごとに別の実行処理、別ファイル、別のアドレス、別のログイン状態を使います。店舗IDを入力して他店を選べる公開APIはありません。
- 店舗の実行処理は非公開のローカルソケットだけで待ち受けます。親の環境変数は許可した項目だけ渡し、既存のバックアップ先・メール送信先・鍵は渡しません。
- 契約管理のパスワードはsalt付きscrypt。既存の店舗管理画面は元の認証方式を継承しています。公開前には認証全体を専門の確認対象とします。
- 契約管理で同じ保存先を二重に起動できません。異常終了後に `service.lock` が残った場合は、記載PIDと関連処理が停止していることを確認してから、このファイルだけを削除します。
- 終了時は子も停止して保存します。親が異常終了した場合も子は停止します。確認が終わったら必ず止めます。
- 同時に起動しておく実行処理数は既定16店舗。上限に達したら、操作中でない店舗を保存して終了し、必要な店舗を読み直します。登録可能店舗数の上限ではありません。上限は最大256まで設定できますが、160〜180店舗の性能・運用費を実測したものではありません。多数店舗の販売前に負荷試験と容量設計が必要です。

## 月額契約

料金は1店舗月額14,800円（税込）。Stripe CheckoutとBilling、請求・解約用のCustomer Portalを使います。Stripeの接続情報がない間は支払いボタンを無効にします。無料期間終了だけで自動課金は始まりません。

公開時に必要な設定は `.env.example` を参照。実際の鍵はホスティングの秘密設定に保存し、ソースや文書に書きません。公開先は既存店舗と別のドメインとし、正規HTTPS証明書と `*.店舗用ドメイン` の経路を設定します。上流の公開入口は転送ヘッダーを上書きし、サービスは外部から直接接続できない内部アドレスに置きます。

1. Stripeの独立した検証環境に商品を1つ作り、JPY・14,800円・月払い・税込のPriceを作成する。
2. Customer Portalで支払方法変更、請求書確認、期間末解約を有効にする。
3. `STRIPE_RESTRICTED_KEY`・`STRIPE_PRICE_ID`・`STRIPE_WEBHOOK_SECRET` を非公開で設定する。権限はCustomer、Checkout Session、Billing Portal Sessionの作成と取得、Price・Subscriptionの読取に限定する。
4. Webhookを `/api/billing/webhook` に登録。対象は `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`、`customer.subscription.created/updated/deleted/trial_will_end`、`invoice.paid/payment_failed/payment_action_required`。
5. テスト決済・失敗・再送・解約・更新を独立環境で通す。戻り先のページだけで契約を有効化しない。署名、環境、Customerの所有店舗、料金、数量、最新の請求状態を確認する。
6. 運営者情報、公開する規約・個人情報方針、問い合わせ体制、保存期間、バックアップ、復元、障害対応を確定してから `LEGAL_APPROVED=1` と本番設定に切り替える。

本番決済は `BILLING_LIVE=1`、`STRIPE_TAX_VERIFIED=1`、運営者情報がそろわないと利用できません。招待番号が必要な小規模導入から開始します。メール送信は既定で無効。送信を有効にする場合は、各店舗の宛先設定と差出人・店舗情報の反映を検証してから `TENANT_MAIL_ENABLED=1` にします。多言語メールは勝手に有効化しません。

Stripeの販売元はACP（課税事業者）と利用者が指定済みです。紹介・導入相談サイトは公開済みですが、予約サービス本体のStripe実接続、独自ドメイン、公開用サーバー、メールの実送信、外部バックアップは未設定です。これらを準備せず「販売開始済み」と案内しないでください。

## 公開前に残る確認

- 各ページの外観と操作、スマホ、8言語、元店舗固有の案内の残りを全件照合する。
- 管理者・会員のパスワード復旧、メールアドレスの確認、退会・記録の出力と削除の運用を確立する。
- Stripeの実環境での試験とCustomer Portal設定、異常時の通知、請求の照合を行う。
- 予約の確認メール、店舗写真・紹介文・各店舗の翻訳、地図表示を店舗ごとに設定する。
- 原本の画面・素材・他社に似た意匠の再販売範囲を確認する。借りた素材をそのまま販売しない。
- 専用環境の負荷・権限・保存・復元の検査、規約の確認、問い合わせ窓口を整える。

収益と販売手順は `事業計画.md`、数字を変えられる試算は `/profit` にあります。


## 導入相談サイトと課税処理（2026-11-22）

[紹介・導入相談ページ](https://store-reservation-service.cnsalon2021.chatgpt.site)をSitesで公開。[相談管理](https://store-reservation-service.cnsalon2021.chatgpt.site/sales)は運営アカウントでのログインが必要。ソースは `launch-site/` の独立した保管先に保存し、本店のGitには入れない。相談情報・候補先・営業原稿も本店のGitに入れない。

月額のCheckoutはStripe Taxを有効にし、請求先住所を収集・保存する。Priceの税込設定は維持する。税の所在地・登録・商品分類と請求プレビューの税額を独立環境で確認した後だけ `STRIPE_TAX_VERIFIED=1` を設定する。既存のACP商品・既存契約・アカウント全体の税分類は変更しない。

Stripe Checkoutの無料期間指定には48時間以上の残期間が必要なため、残り48時間（処理の余裕60秒を含む）未満の新規有料申込みは無料期間の終了まで待つ案内にする。残りの無料期間を省いて即時課金しない。

実施した販売準備、専用サーバー案と未完了事項は `販売開始の進捗.md` を参照。
