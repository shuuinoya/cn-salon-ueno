# 回数券の再点検（2026-11-03）

対象は回数券の購入・管理画面からの購入登録・予約時の利用・取消時の返却・画面間の反映です。送信設定・送信待ちメールを除去した本番コピーを使用し、外部通信・外部保存を停止。検証用の会員名には「テスト」を付けています。

## 再現して修正した問題

- 購入確認中に別タブでログイン会員を切り替えると、表示していた名前と購入先がずれる。確認時の会員・管理者と送信時のログインを照合し、不一致では券やメールを作成しない。確認後に会員情報が変わった場合も、初回購入を止める。購入成功後の再確認では既存の結果を返す。
- 検索結果を作る全角・半角変換が購入先メールにも適用され、異なる会員を選ぶ可能性があった。検索と本人の識別を分け、登録メールを維持。全角を含む会員と半角の会員が同時に存在する例で確認。
- 応答不明の購入を再確認するとき、販売停止済みの券では画面を開けなかった。販売中の一覧よりも保存した購入確認を優先し、販売中の券がなくても再確認する入口を表示する。
- 店内のHTTP接続などでは `crypto.randomUUID` が使えず購入処理が止まる。HTTPでも使用できる暗号用乱数で購入番号を作成。

大量検査は修正後に実施し、追加で見つかった会員識別の修正後にも再実行。最大50件の同じ購入要求が同時に届いても、購入券と購入メールがそれぞれ1件であることを確認します。

実画面では、A会員で確認を開く→別タブでB会員へログイン→購入を押す、の手順で購入を停止。券0件・メール0件を確認。元のA会員に戻って同じ購入を再確認すると、連打しても券1件・メール1件だけになりました。

本番では保存記録を読み取りだけで照合。券ID重複、残数範囲外、購入履歴の重複、会員の保有券リンク重複、持ち主の不一致、参照先のない購入確認キーはいずれも0件でした。本番で予約・購入・設定のテストは行っていません。

## 確認範囲の限界

同じ購入操作の再送を1件として扱います。別の画面・別の端末で新しく購入を確定した操作は、追加購入と区別できないため一律にはまとめません。実際のスマホ端末固有の操作、端末故障、すべての将来の条件まで問題が起きないことを保証する検査ではありません。
