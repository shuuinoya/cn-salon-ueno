# 回数券の画面整理と大量検査

2026年10月24日。お客様画面と管理画面をコンパクトに整理し、回数券の利用・購入・取消・残数調整を検査しました。

## 画面

- 保有券：券名、対象メニュー、購入日、有効期限、残り回数、「使用する」。利用済みの内訳などは「詳細を見る」で開く。
- 購入欄：使える保有券がある場合は折りたたむ。従来の購入操作・価格・条件は保持。
- 管理画面：「お客様の回数券／販売・設定」の切り替え、名前・メール・券名検索、予約ボタン、詳細内の履歴・調整・メール確認。
- スマホ390px、タブレット768px、パソコン1280pxの表示幅で確認。スマホの操作欄が旧来の表の最小幅に押し出される不具合と、ドイツ語のタブが横へはみ出す不具合を修正。
- 削除済みメニューしか対象にない券は、使用開始ボタンを非表示。券の記録は残す。
- 「詳細を見る」を8言語で用意。毎月8〜14日の案内を保持。

Figmaへ送ったのは架空の見本・共通部品のみ。画面の取り込みは自動承認審査で拒否されたため実施せず、架空の見本作成に切り替えた。その後Figmaの利用上限に達したため、完成したFigma資料はない。実際のサイトの検証画面で表示・操作を仕上げた。

## 方法と範囲

本番から読み取ったコピーを独立した一時フォルダに置き、送信設定・送信待ち・ログイン情報を除去。外部通信・保存・メールを無効にした。実装の予約処理・回数券処理を呼び出し、条件ごとに架空のお客様・担当・予約で状態を初期化。テスト名は必ず「テスト」を含む。本番では試しの購入・予約・取消を行っていない。

| 条件 | 通り数 |
| --- | ---: |
| 24メニュー、会員・ゲスト・管理受付、券の所有者・残数・期限・対象、勤務・スキル・ブロック・時間 | 5,184 |
| 月末・うるう年などの期限計算 | 2,480 |
| 回数・期限の調整と不正入力時の全記録保持 | 507 |
| 購入再送、別内容・別所有者・販売停止後の再送 | 54 |
| 期限切れ分の復活、対象メニュー・組の違い | 288 |
| 各25操作の予約・取消・再利用と残数照合 | 120 |
| 販売プランの数値入力 | 56 |
| 回数券予約の時間・所有者変更 | 24 |
| 保存状態からの復元・復元後の取消返却 | 2 |
| 2・5・10・25・50件の同時購入・予約・最後の1回の競合 | 20 |
| **合計** | **8,735** |

最終結果：8,735通り成功、失敗0、39,281項目を照合。初回8,709通りでは277通りが失敗し、追加の予約変更検査では24通り中6通りが失敗した。以下を直して再実行した。

1. 残数調整と期限変更を両方検証してから一括更新。不正な期限で残数だけ変わる事態を防ぐ。小数・空白・無限大・範囲外・理由が空白だけの入力を拒否。
2. 購入の同じ送信番号に別内容を指定した場合は拒否。正常な再送は販売プランが停止・削除されても購入済みの結果を返す。旧形式で内容を照合できない番号は拒否して二重発行しない。
3. 販売プランの価格・回数・期限を勝手に丸めず整数で検証。不正な追加で番号だけ進まないようにする。
4. 回数券利用済み予約の合計施術時間と所有者メールを固定。開始時刻と対応できるスタッフの変更は維持。

- 回数券表示・日本時間・復活ラベル・未登録日・8言語・設定権限・既存価格と残数の保持も成功。
- ブラウザーで詳細開閉、購入欄の折りたたみ、検索一致・該当なし、設定切り替え、メール履歴表示、検索後の閉じる、未保存の入力保持を確認。
- お客様の「使用する」からメニュー・日時・予約確認へ進み、選択した券がそのまま選択されることを確認。
