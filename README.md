## セキュリティ（個人情報・予約情報・会社情報の保護）
- サーバーは **127.0.0.1（このパソコンの中）だけで待ち受け**ます。同じWi-Fiの他の端末やインターネットからは一切接続できません
- 予約・顧客・シフトなどのデータは**メモリ上のみ**で、ファイルにも外部にも保存・送信されません（サーバー再起動で消えます）。メールも実際には送信しません
- **Hostヘッダ検証**（DNSリバインディング対策）：偽のドメイン名経由でローカルサーバーへ到達させる攻撃を403で遮断します
- **Origin検査**（CSRF対策）：悪意ある別サイトのページからの予約作成・設定変更などの書き込みを403で遮断します
- **セキュリティヘッダ**：`X-Content-Type-Options: nosniff`／`X-Frame-Options: DENY`（他サイトへの埋め込み禁止）／`Referrer-Policy: no-referrer`（参照元を外部へ送らない）
- 外部のCDN・解析タグ等への通信はありません（画像・JS・CSS・フォントはすべてローカル配信。元サイトのCloudflareボット判定コードも除去済み）

元サイト https://cn-salon-ueno.cnsalon2021.chatgpt.site を、2026年9月24日時点のまま保存したものです。
`pages/` と `public/` の中身は基本的に元サイトのままです。例外は、追加したページ（demo-admin.html・pm-login.html・not-found.html）と、予約確認・完了ページのラベル折り返しバグを直すために最小修正した3ファイル（BookingText-*.js・page-WafCof8Y.js・page-ChO0-Npx.js）です。

## VS Codeでの開き方
1. VS Codeで「ファイル → フォルダーを開く」から、このフォルダを開く
2. F5 を押す（「サイトを起動」）→ ブラウザが自動で開きます
   - 開かない場合は http://127.0.0.1:5520 を開いてください（ほかのサイトと混ざらないよう、専用の番号で起動します）
   - ターミナルで `npm start` と入力しても起動できます（Node.jsが必要です）
3. 止めるときは、VS Codeの上に出る停止ボタン（■）を押します

※ Live Server拡張機能では一部のページが正しく表示されないため、上の方法で起動してください。

## 管理画面（復元版）
店舗用の管理画面のHTMLは保存されていませんでしたが、JavaScript本体（`AdminSchedule`）は
保存されていたため、次の3点を追加して **http://127.0.0.1:5520/admin （または /demo/admin）** で
操作デモ版を開けるようにしています。

- `pages/demo-admin.html` … 保存済みのRSCペイロード形式を流用して生成したページ（`tools/make-demo-admin.py` で生成）
- `public/_next/static/css/AdminSchedule.B6xQvMXS.css` … 元サイトでは配信されていなかったため、クラス構造から再作成したCSS
- `demo-api.js` … `/api/demo/schedule` などを架空データで再現（サーバー再起動で初期状態に戻ります）

予約台帳（日別・月間シフト）・シフト編集・休憩/業務の登録・新規予約・予約取消・
スタッフマスタ編集が架空データ上で一通り操作できます。本番のデータ・メール送信には
一切影響しません。ページを開いた直後にコンソールへ出る React エラー #418 は、
管理画面のサーバー描画HTMLが存在しないことによる想定内の表示で、動作に影響はありません。

## お客様の予約（動くようにしてあります）
日時選択ページの空き状況・スタッフ指名・予約の送信も、管理画面と同じ架空データで動きます。
お客様の予約もそのまま通せます。

- 空き状況の○×は、管理画面の**シフト・休憩/業務・既存予約・対応メニュー・受付停止**から計算されます
- スタッフ情報の**対応メニュー（チェックボックス）**は、指名あり・指名なしの両方の担当決定に完全連動します。チェックのないメニューのスタッフは候補から除外され、画面を直接操作してもサーバー側の再チェックで拒否されます。チェックを外したメニューに今後の予約が残っている場合は、予約は維持したまま管理画面に警告が出ます
- スタッフ指名（指名料）は、スタッフ情報の**個人指名・指名料**の設定が反映されます。料金・指名料は**予約確定時点の値**で保存され、あとから設定を変えても過去の予約は変わりません
- 複数名の予約は、人数分の対応可能スタッフをまとめて確保します（担当変更・取消時も全員分を更新）
- 予約の担当変更（別スタッフへ移動）は、変更先の対応メニュー・シフト・休憩・既存予約を再確認し、指名予約は**変更先の指名料で再計算**されます
- 上部メニュー「店舗情報 → 店舗情報」で、予約フォームの**フリーメッセージ欄**（表示／必須／見出し／placeholder／説明文／文字数制限）を設定でき、予約サイトへ即時反映されます。入力内容は台帳・通知メールまで届きます
- 「店舗情報 → メニュー一覧」で**メニューの追加・変更・削除・写真の登録**ができます。空き状況・予約金額・管理画面の予約フォームの選択肢に即時反映されます（予約が入っているメニューは削除不可。料金変更は新規予約のみに適用され、確定済み予約の金額は変わりません）。写真は各メニューの「写真登録／写真変更／写真削除」から差し替えでき、縮小して保存されます（メモリ上のみ・再起動で消えます）
- 「日次管理 → 営業実績」で、本日の売上・来店数・オンライン予約数・シフト状況・明日の出勤スタッフなどを**予約とシフトの実データから自動集計**した日報画面が見られます（天気・実施プラン・担当者の一時保存／日報送信つき）
- お客様が予約すると、**管理画面の予約台帳にその場で表示**されます（逆に、台帳で予約を取り消せば枠が空きます）
- 予約完了ページの予約番号・合計金額も本物と同じ流れで表示されます
- 予約の完了・変更・取消時に、お客様宛と店舗（管理者）宛のメールを自動生成します（実際には送信せず、 http://127.0.0.1:5520/admin/mails で件名・本文・送信状態まで確認できます）
- メールは「送信予定 → 送信処理中 → 送信済み／送信失敗」の状態で管理され、送信済みは配信サービスの成功応答を確認してから記録します。同じメールが二重送信されることはなく、取消した予約のリマインドは送信されません
- リマインドメールも自動登録されます（お客様＝来店24時間前、店舗＝当日朝9時）。予約変更時は変更後の内容で再登録されます
- データはメモリ上のみ。サーバー再起動で初期状態に戻ります

## 保存版で使えないもの
元サイトのサーバー側の機能なので、ファイルとしては保存できません。
- お客様向けのログイン（予約は上記のとおり架空データで動きます）
- ページ移動は毎回ページ全体を読み込みます（表示される内容は同じです）
- 店舗用の管理画面（/admin）の本来のサーバー機能（上の「管理画面（復元版）」は架空データの操作デモです）

## 補足
元サイトの配信会社（Cloudflare）が、ダウンロードしたときだけHTMLに自動で差し込むボット判定用のコードは取り除いています。
取り除いた結果が、ブラウザで元サイトを開いたときのHTMLと完全に一致することを確認しています。
